# Changelog

All notable changes to `omegaquiz` are recorded here. Format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); this project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- **Hide the speaker buttons.** Admin → Branding → Presentation gains *Speaker button on the board* and *Speaker button on phones* (`showSoundToggleBoard` / `showSoundTogglePhones`, `SHOW_SOUND_TOGGLE_BOARD` / `SHOW_SOUND_TOGGLE_PHONES` env). The board now remembers its last sound setting per browser (it always started muted) and **M** toggles it from the keyboard.
- **The admin page remembers its tab.** The active tab is kept in the URL (`/admin#players`) and in the browser, so a reload stays on Players (or Questions, Settings…) and a fresh visit opens the last tab used; every reload went back to Overview before. A reconnect no longer replaces unsaved question edits with the server's copy (it says the edits are kept), and a save from another admin page while you have unsaved edits keeps yours and offers Save or reload.
- **Question timer.** Admin → Branding → *Question timer* (default 45 s, 0 = off, `QUESTION_SECONDS` env) and a per-question *Time limit* (`seconds` in JSON packs and a new optional CSV column). The server owns the deadline: every state carries `timer {deadlineAt, seconds, locked, serverNow}` while a question is open. The board draws a ring, phones a bar, Admin → Overview a *Time left* tile and the presenter view a pill; the last five seconds go red and tick in dramatic mode. When time is up answers lock (`player:answer` refused, phones say *Time's up*) but the reveal stays manual. Lifelines do not pause it; rewinding restarts it; Back to lobby, close, skip and reset clear it.
- **Stop or rewind a live game.** Admin → Overview and the presenter view gain a *Stop or rewind* row (two-click buttons: arm, then act within 5 s). **Back to lobby, keep players** now works from any question, reveal or the results — it used to be allowed only on question 1 with nobody out — and returns everyone alive on zero with the same join code and fresh lifelines; phones get `game:lobby-return` and say so. New host action **`rewind-to` `{index}`** re-asks a main question already asked and replays each player's kept history so scores and knock-outs from that question on are undone; used lifelines stay used. Every state carries `rewinds` so the board and phones treat a re-asked question as new.
- **Presenter view.** `/present` (host or admin) is the facilitator's screen while the board is on the projector: the current question with the correct answer marked and the lesson before the reveal, the live answer split, who is still to answer, what comes next (the next question with its answer and notes, the tiebreaker marked conditional, or the end), the controls and lifelines, the Ask IT hint, and how long the question has been open. New WebSocket screen `present:hello` / `present:state`; Admin → Overview has **Open Presenter View**.
- **Presentation clicker on the presenter view.** Page Down / → / Space does the next natural thing (start, close & reveal, next; a second press within 0.7 s is ignored); Page Up / ← looks back through past reveals — question, room split, lesson — on the presenter's screen only, and forward returns to the live view without advancing. A **Clicker armed** pill shows when the page has focus. `present:state` carries `history` (closed questions with their tallies and notes); the board and phones get nothing new.
- **Presenter notes per question.** A plain-text `notes` field (Admin → Questions, the `notes` column of the CSV export and template, and JSON packs) that only the presenter view shows: it is never in `host:state`, `player:state`, the post-game review or `/lessons.json`. CSV files without the column still import.
- **The lesson is on screen at the reveal.** The board shows it as a **Why** panel under the answers (the question block tightens up so answers, tally bars and lesson fit a 1280×720 projector), every phone shows it under its answers and scrolls it into view, and Admin → Overview shows it as the **Talking point** under the current question. `player:state` carries `question.lesson` at the reveal only.
- **Admin help for running a question.** **Still to answer** lists who is still in and has not answered (online first, offline marked); while a lifeline vote is open the **Apply** buttons show each available lifeline's votes with the leader marked (they read "Apply 5050 / ASKIT / SKIP" before, including spent ones); Admin → Players has a name/email search; at the end of the game **Download results** sits next to Reset.
- **Lobby helpers.** The board prints the join address beside the QR in large type (the address the QR encodes: Public server URL, else `PUBLIC_BASE_URL`, else its own origin; `host:state` carries `envPublicBaseUrl`) and lists the newest names first, animating only new ones. In dramatic mode the board lobby offers **Turn on sound** and phones **Tap to turn on sound**, so the first question doesn't land silently. The phone lobby says what to expect.

- **Quiz title is editable in Branding.** The host board used to read "<company name> Omega Quiz" with no way to change the second line except a sample-pack load or the `QUIZ_TITLE` env var. Admin → Branding now has a **Quiz title** field with a live preview; leaving it blank shows the company name alone. The configured title also drives the player screen, the browser-tab titles, the results email subject and the sign-in page, none of which hard-code "Omega Quiz" any more. Missing taglines no longer leave the host board's placeholder subtitle on screen.
- **End-of-game actions on the player screen.** **Email me my results** now sits on the final screen itself, not only inside the results breakdown, and Admin → Branding gains an optional **End-of-game CTA** (label + `https://`/`http://`/`mailto:` link, also via `END_GAME_CTA_LABEL` / `END_GAME_CTA_URL`) rendered as a button on every player's final screen — for example *Book time with IT*. The host board's results screen spells the same link out.
- **Dramatic presentation mode.** Admin → Branding → **Presentation** (or `PRESENTATION_STYLE=dramatic`): a suspense sting and staged option reveal when a question lands on the board, a drum-roll before the answer is shown, and tap / lock-in / result sounds with sweeping transitions on the phones, which hold the reveal for the same drum-roll so the answer never appears on a phone before the board. Sounds are synthesised in the browser; each screen keeps its own speaker toggle (the phones gain one) and reduced-motion is honoured. Standard mode is unchanged.
- **Re-key without a restart.** `node server.js remint <admin|host|all>` rotates a recovery token in place and `node server.js links [role]` mints fresh single-use magic sign-in links, both from a shell on the server (`fly ssh console -C "node /app/server.js links"`, `docker exec …`). The running server picks the new values up lazily — on the next recovery sign-in or the first click of the link — so nothing restarts and nobody is signed out. Works for tokens kept in `DATA_DIR/secrets.json` (`AUTO_PROVISION_SECRETS=true`, the `fly.toml` default); env-managed tokens are refused with a ready-to-paste `fly secrets set` line instead. Run as root (as `fly ssh console` does), the subcommands drop to the owner of `DATA_DIR` so the server can still read what they write.
- **Admin → Settings → Sign-in & keys.** Mint a new host or admin magic link (the `auth:mint-magic-link` action existed but had no UI), rotate either recovery token (`auth:rotate-recovery-token`), and see where each token comes from (`admin:init` now carries `keys`; `auth:keys-status` on demand). Rotated values are shown once, to the requesting socket only.
- `just remint`, `just links`, `just fly-remint`, `just fly-links` recipes, and a "Keys — lost, expired or compromised" section in `docs/DEPLOYMENT.md`.
- `getClientIp(req, policy)` accepts an explicit trust policy (`mode` / `hops` / `onFly`) so tests can exercise Fly and multi-hop deployments in-process. `forwardedIpFromRight`, `pruneExpiredState`, `inMemoryStateSizes` and the policy constants are exported for the test harness.
- **JSON import in the Questions tab.** *Import CSV* is now *Import CSV / JSON* and accepts the same `{ title?, category?, tagline?, main, bonus }` pack format as `samples/*.json` and *Export JSON*, so a pack downloaded from GitHub imports as-is. Pack metadata is applied to branding exactly as a sample-pack load would. New admin action `questions:import-json`; `questions:imported` now carries `format` (`csv` | `json`) and `brandingUpdated`; sample-pack errors carry `scope: "samples"`.

### Changed

- **Ties share places at the end.** The board's ceremony and results used to number players 1, 2, 3… in alphabetical order within a tie, so two survivors on the same score produced "And the winner is…" for whoever came first alphabetically. Places now follow competition ranking (1, 1, 3), the ceremony names a shared place together ("Joint 4th place…", "And our joint winners are…") and covers the places inside the top five, and with no survivors the results are titled **Top Scores** (was "No survivors!"). The in-game survivors panel is unnumbered.
- **The board's answered count only counts players still in** (`answeredCount` on `host:state` / `admin:state`). Knocked-out players answering along, or the players just knocked out at a reveal, made it read "33 / 23 answered". At the reveal the board now says how many were knocked out.
- Reset on the board's results screen asks first, and the admin confirmation says the results cannot be recovered afterwards. During a game Admin → Players lists offline players first.
- Scores read "1 pt" / "N pts" on the phones, the board and the results email.
- `secrets.json` is written atomically (temp file + rename) and records `rotatedAt` per role. `HOST_TOKEN` / `ADMIN_TOKEN` are mutable inside the process; `COOKIE_SECRET` is not.
- Structured JSON log lines are suppressed while a subcommand runs — its output is for a human.
- **One pnpm version pin.** The `packageManager` field in `package.json` is the single source of truth. The Dockerfile (hard-coded 11.1.3) and `render.yaml` (Corepack + 11.0.6) now resolve the version from `package.json` at build time and install it with `npm install -g`. Corepack is no longer used anywhere: Node 25+ does not bundle it.
- **Supported Node is now 22.13 or newer** (`engines.node`), and the CI matrix is Node 22 / 24 / 26 instead of 18 / 20 / 22 / 24. pnpm 11 refuses to run on older Node, which is why the Node 18 and 20 jobs had failed at `pnpm install` on every run since May; both versions are also end-of-life.
- **The `Test` workflow is enabled again.** It had been disabled manually while every run was red for the two reasons above. It runs on push, pull request and nightly.
- Docs: README and CONTRIBUTING quick-starts use `npm install -g pnpm` instead of `corepack enable`; the test count and Node matrix are current; CONTRIBUTING records that Renovate (shared `privacykey/renovate-config` preset) is the only dependency bot and that Dependabot was retired.
- `.env.example`: `TRUST_PROXY` comment rewritten around hop counting and the platform headers.
- `pnpm-lock.yaml` is no longer copied into the Docker runtime stage. Nothing reads it at runtime; the `deps` stage still uses it for `pnpm install --frozen-lockfile`.
- New `A11Y:` test sections assert the served markup keeps every fix above: tab/tabpanel wiring and key handling, the live region and absence of the auto-dismiss, form semantics, `aria-pressed` / `disabled` / state text on answers, the computed contrast ratio of every state fill, zoomable viewports, and no inline `on*=` handlers on any page.
- Test suite: 519 → 857 checks across the changes above (re-keying and WebSocket robustness, sample packs and JSON import, forwarded-IP policy and the expired-state sweep, accessibility markup, quiz title / host screen / presentation, event hardening, message budget and join limits, presentation and admin polish, restart with a saved image bank).
- **Fly connection limits raised to 1,000 (soft 800), from 200 / 150.** Fly counts TCP connections and each phone usually holds two, so 80 phones could reach the old soft limit and approach the hard one, where Fly queues new connections and then returns 503s. One Node process holds 1,000 idle sockets without measurable memory growth.
- **`/health` is minimal in public.** Anyone could read the game phase, player count and uptime; the public response is now `{"ok":true}`, and a signed-in admin still gets the details. Responses no longer send `X-Powered-By: Express`.
- **Rejoining is no longer time-limited.** `PLAYER_RECONNECT_WINDOW_SECONDS` now only sets how long Admin → Players lists a dropped player as *Disconnected* before *Offline*, and the roster's **Extend** button is gone. Join errors carry a machine-readable `code` (`wrong-code`, `rate-limited`, `email-taken`, `game-started`, …) next to the message.

### Fixed

- **A saved question bank with any question image came back empty after every restart.** The boot-time load of `DATA_DIR/questions.json` ran before the image size and type limits it checks were initialised, threw on the first image, and fell back to an empty bank without a word: a deploy, crash or Fly host move mid-session left the board with "No questions loaded yet". The limits are now declared first, and a saved bank that still cannot be loaded is reported at boot.
- **The Ask IT hint was cut at the first full stop,** so a lesson starting "Look-alike domains (paypa1.com vs paypal.com) are…" showed "Look-alike domains (paypa1." It is now the first whole sentence (not ending after "e.g." or "i.e."), shown as text.
- **The Ask IT pop-up stayed on the board** over the reveal and the next question until someone closed it. It now closes when its question is revealed or the game moves on.
- **The phone's Lock In button showed HTML entities** ("Lock In B: The sender domain uses a &#39;1…"). It shows the option as text.
- **Phones that dropped without a goodbye were locked out.** A phone that lost Wi-Fi, switched networks or was suspended by iOS usually reconnects before the server notices its old connection is dead, and was refused ("The game has already started — joining is closed", or "That email is already registered" in the lobby). The refusal landed on the hidden join form, so the phone froze on its last screen. A phone presenting its saved seat with the same name and email now gets it back in any phase, taking over the old connection; the old connection is told why and closed with code 4001, and its late close no longer marks the player offline.
- **Early arrivals whose phones slept for more than five minutes could not get back in,** not even by filling the form in again. Rejoining with the saved seat is no longer limited by the reconnect window, and in the lobby the same email from another device takes over a seat whose phone is offline.
- **First-time players never rejoined automatically after a drop.** The join form saved the name and email to storage but not to the in-memory copies the automatic rejoin reads, so a phone that had not reloaded since joining reconnected its socket and sat unbound.
- **Eight wrong join codes blocked a whole office network for five minutes.** Everyone on one Wi-Fi shares one public address. The default is now 30 a minute (`JOIN_FAILURE_MAX`), and a phone rejoining its own seat is never counted or blocked.
- **A restart mid-session locked the room out.** Every phone rejoined with the old code, the first eight failures tripped the limiter, and people scanning the new QR were refused for five minutes. The join code is now kept in `DATA_DIR/game.json` and survives restarts, so phones re-register in the fresh lobby by themselves. **Reset game** still issues a new code.
- **Reset game left connected phones frozen on the old game, and the host board kept showing the old QR.** Phones are now told (`game:reset`), forget the old code and return to the join form; the board reloads the QR whenever the join code changes, and `/qr` is served `Cache-Control: no-store`.
- **With 60+ players the host lobby pushed Start Game off a 1280×720 screen** and squeezed the name list to nothing. The lobby scrolls, the list keeps its height, Start Game stays pinned to the bottom edge when the lobby overflows, and short screens get a smaller QR and code.
- **Every answer re-sent every phone its whole state.** With 80 phones that was 80 × 80 messages a question, question image included: a 150 KB screenshot came to about 980 MB a question, and with 30 phones on weak Wi-Fi a 256 MB server ran out of memory and exited. An answer, lifeline vote, join or return now updates only that phone plus the board and admin; a phone leaving updates only the board and admin.
- **No WebSocket heartbeat.** Silent connections stayed "online" until TCP gave up. The server now pings every 30 s and drops a connection that missed the previous ping.
- **Phones retried every 1.5 s in lockstep** after a drop or restart. Retries now back off with random jitter, and a phone reconnects immediately when it comes back on screen or back online.
- **Host board stayed on `----` when opened with the admin session.** `/host`, its `host:hello` handshake and `/qr` all accept the admin session, but the `host:state` push was filtered on `role === 'host'`, so an admin on the host screen got the page and the QR code and never the game state — no join code, a Start button that never enabled. Sockets are now subscribed by the screen they announce (`host:hello` / `admin:hello`); host-role sockets that never say hello keep receiving pushes as before. The host board also now says when no game state has arrived within a few seconds instead of sitting on dashes silently.
- **Bundled sample packs were missing from the Docker image.** The `Dockerfile` runtime stage copied `server.js`, `questions.js`, `package.json` and `public/` but never `samples/`, while the default `SAMPLE_PACKS_URL` (`bundled:samples/manifest.json`) resolves that directory on disk next to `server.js`. On every Dockerfile-based deploy (Fly.io, Railway, self-hosted Docker) Admin → Questions → **Browse sample packs** failed with `Sample browse failed: ENOENT: no such file or directory, open '/app/samples/manifest.json'` — the exact first-boot flow `docs/DEPLOYMENT.md` points operators at. Render's native Node runtime was unaffected. The runtime stage now copies `samples/`, and a new `image-contents` CI job builds the image and fails if any `samples/*.json` from the checkout is missing from `/app/samples` (checked as the unprivileged `app` user, on every PR including forks).
- **"Browse sample packs" looked like a timeout when the packs were missing.** The server's error reply was rendered in the banner area *underneath* the modal overlay, so the modal sat on "Loading…" forever. A missing bundled pack now produces a clear `missing from this deployment` error instead of a raw `ENOENT` + path; the boot banner prints `Samples: NOT FOUND` when the directory is absent; and the sample-packs modal shows failures inline with a **Retry** button (and gives up after 15 s if no reply arrives at all).

### Security

- **HIGH — One player could crash the server by flooding answers.** Nothing limited how many messages a connection sent, and every answer queued fresh board and admin updates; on a 1 CPU / 256 MB server about 8,700 answers a second from one phone exhausted memory in under 20 s. Phones and anonymous sockets now get a message budget (bursts of 20, 5 a second sustained; host and admin are exempt); messages over it are dropped before parsing and a connection that keeps flooding is closed with 1008. Separately, board, admin and phone updates are complete snapshots, so a connection more than 1 MB behind now gets only the newest one of each kind once it drains instead of a growing queue, and repeating the same answer no longer triggers any update.
- **MEDIUM — One connection could add unlimited players.** A connection that already held a seat could keep joining under new emails: 300 fake names from one socket filled the lobby and the projector, each needing its own Kick. A connection now holds one seat (`already-joined`), and new players per public address are capped at 150 per 10 minutes (`JOINS_PER_ADDRESS_MAX`, `join-cap`); rejoins don't count and Reset game starts the count again.
- **LOW — Email addresses had no length limit.** A 15 KB address was accepted and resent to the admin on every update. Addresses are capped at 254 characters, the longest SMTP allows.
- **HIGH — One unauthenticated WebSocket message crashed the server.** A frame containing the JSON literal `null` threw on `msg.type` in the message handler; the exception reached `uncaughtException`, which shuts the server down and drops every phone. No sign-in or join code needed. Non-object messages are now ignored, and the whole handler runs inside a try/catch that logs `ws.handler-error` and carries on.
- **HIGH — A join with a non-string name crashed the server.** `player:join` with the right code (readable off the projector) and a number or array as the name, or an array as the email, threw on `.trim()` / `.toLowerCase()`. Join fields must now be strings.
- **MEDIUM — Ask IT sent the correct letter to every player's phone.** The phones never displayed it, but it was readable in browser developer tools. `lifeline:askit` now goes to host and admin sockets only.
- **HIGH — One oversized WebSocket frame from an unauthenticated visitor crashed the server.** `ws` re-emits protocol errors (frame over `maxPayload`, invalid UTF-8) as an `'error'` event on the socket; no listener was registered, so the event became an `uncaughtException` and ran the full graceful shutdown. A single 5 MiB frame dropped every player and restarted the process (reproduced against `main`). Patched: per-socket `'error'` listener that logs `ws.socket-error`, plus a 16 KiB cap on messages from non-admin sockets, closed with 1009 before parsing.
- **HIGH — Per-IP rate limits were spoofable behind appending reverse proxies (Fly, Render, Railway, Docker + nginx).** `getClientIp` took the *first* `X-Forwarded-For` entry, but every mainstream proxy *appends* the address it accepted the connection from to whatever the client sent, so the first entry was attacker-controlled. A client could present a fresh "IP" on every request, which sidestepped the login limiter (5 tries / 15 min guarding `HOST_TOKEN` / `ADMIN_TOKEN`) and the join-code limiter (8 tries / 60 s guarding the 6-digit join code), and grew `loginFailures` / `joinFailures` without bound because entries were only pruned on success. `CF-Connecting-IP` was also honoured from any private peer, not only from a Cloudflare edge. Patched: `X-Forwarded-For` is now read from the **right**, walking `TRUST_PROXY` hops (Express `proxy-addr` semantics; a non-IP in the trusted slot falls back to the socket peer instead of skipping left into client-supplied entries); `Fly-Client-IP` is preferred when the process is a Fly Machine (`FLY_APP_NAME` / `FLY_MACHINE_ID` / `FLY_ALLOC_ID` present) with a single trusted hop, as [Fly's request-header docs](https://fly.io/docs/networking/request-headers/) recommend; `CF-Connecting-IP` only counts when the socket peer *is* a Cloudflare edge (or `TRUST_PROXY=always`). Found in the 2026-09 pre-ship audit.
- **MEDIUM — Unbounded in-memory state.** Login / join failure buckets and sessions were only removed on success or on next use. A 60-second sweep (sharing the existing magic-link timer) now drops failure entries whose window and block have both expired, expired sessions, and expired magic links. Decisions are unchanged: the sweep only removes what the hot paths already treated as expired.
- **`qs` and `body-parser` advisories closed with pnpm override floors.** `pnpm audit --prod` reported three moderate advisories in `qs` 6.15.1 (GHSA-q8mj-m7cp-5q26, GHSA-x5fp-wj9c-mxmx, GHSA-4mjr-xmp4-gh2g) and one low in `body-parser` 2.2.2 (GHSA-v422-hmwv-36x6), all transitive via `express`. New `pnpm-workspace.yaml` sets `overrides` of `qs >=6.16.0` and `body-parser >=2.3.0` (pnpm 10+ no longer reads a `pnpm` field in `package.json`); the lockfile now resolves 6.16.0 / 2.3.0 and the audit is clean.
- **`aquasecurity/trivy-action` pinned to a commit SHA** (`ed142fd0…`, v0.36.0), matching every other action in the workflow. The old `@0.36.0` ref pointed at a tag that does not exist upstream (releases are tagged `v0.36.0`), so the container-scan job had failed at set-up on every run.
- **Docker runtime image applies Alpine security patches and no longer ships npm** (nor npx, corepack or yarn). With the scan able to run for the first time, Trivy flagged the base image itself: `libcrypto3` / `libssl3` CVE-2026-14456 (fixed in 3.5.8-r0) and HIGH advisories in npm's own bundled `brace-expansion`, `ip-address` and `tar`, none of them application dependencies. The runtime stage now runs `apk upgrade --no-cache` and removes npm / npx (nothing at runtime uses them; the CLI is `node server.js …`). The image scans clean with CI's flags and `/health` still answers.

### Accessibility

Closes six confirmed WCAG 2.2 AA findings from the pre-ship audit follow-up. Mouse users only see darker state colours and a few extra words; keyboard and screen-reader users get working tabs, a submittable join form and answer states they can actually perceive.

- **Admin tabs are real tabs.** The six dashboard tabs were `<div>`s with a click listener — unreachable by keyboard and not announced. They are now `<button role="tab">` inside a `role="tablist"`, with `aria-selected`, `aria-controls`, a roving `tabindex` and Left/Right/Home/End arrow-key navigation; every panel is a `role="tabpanel"` labelled by its tab. The Branding form still lazy-loads on first show, now regardless of whether the tab was reached by click, keyboard or the Overview "View all" button — which is now a `<button>` (it was an `<a>` with no `href`).
- **Player answer state is no longer colour-only.** Each answer button's accessible name ends with its state ("— your answer", "— correct", "— wrong, your answer", "— removed by 50/50"), the selection is exposed via `aria-pressed`, options removed by 50/50 are genuinely `disabled` (previously only `pointer-events:none`, which did not stop Enter/Space), and a visible text tag (✓ Correct / ✗ Your answer / Selected / Removed, plus strike-through) mirrors the colour.
- **Pinch-zoom re-enabled on the player page** — `user-scalable=no` removed from the viewport meta (WCAG 1.4.4).
- **Join screen is a real `<form>`.** Enter and the phone keyboard's Go key now submit; inputs carry `required` and `aria-describedby` pointing at the error message; on a validation or server error the offending field gets `aria-invalid="true"` (red ring) and takes focus. The error no longer auto-hides after 4 s — it stays until the next attempt or a successful join.
- **Contrast.** Selected/pending answers (white on `#d97706`, 2.9:1), correct answers (white on `#16a34a`, 3.0:1), wrong answers (4.3:1 after opacity), the Lock In button (white on `#22c55e`, 2.3:1) and the host projector's correct-answer letter (gold on `#16a34a`, 2.0:1) now use darker fills (`#9a3412`, `#15803d`, `#b91c1c`) with white letters — every state is ≥ 5.0:1.
- **Admin banners are announced and stay put.** `#banner-area` is a `role="status"` polite live region, and the 5 s auto-dismiss on success banners (JS timer plus the CSS fade-out) is gone; the existing Dismiss button closes them.

## [1.1.1] - 2026-05-19

Blue-hat security audit follow-up. Closes nine findings raised in a Railway-targeted review, none of which were caught by the existing 487-check suite.

### Security

- **HIGH — Remote unauthenticated DoS via malformed cookie on WebSocket upgrade.** `parseCookies` called `decodeURIComponent` unguarded; a single WS upgrade with `Cookie: omegaquiz_sess=%X` threw `URIError`, escaped the `wss.on('connection')` handler, and tripped the `uncaughtException` listener into `gracefulShutdown` — i.e. one packet, one full restart. Patched: `parseCookies` now swallows malformed `%` sequences and treats the raw value as opaque (the cookie verifier rejects it downstream).
- **HIGH — Login rate-limiter was non-functional.** A fresh entry started with `blockedUntil = 0`, which is always `< Date.now()`, so the "reset expired block" branch fired on every call and the counter never reached 5. `HOST_TOKEN` / `ADMIN_TOKEN` brute-force was effectively unthrottled. Patched: mirrored the `recordJoinFailure` shape with a `firstAt` field and an explicit `LOGIN_WINDOW_MS` window check.
- **MEDIUM — `getClientIp` ignored Railway / Render / Fly reverse proxies**, collapsing every per-IP rate-limit bucket to one entry (the PaaS edge IP). Patched: `TRUST_PROXY=auto` (default) trusts `X-Forwarded-For` when the socket peer looks like a reverse proxy (loopback / RFC1918 / 100.64-CGN / Cloudflare edge / IPv6 ULA + link-local). `TRUST_PROXY=1` forces trust, `TRUST_PROXY=0` disables it.
- **MEDIUM — Open redirect on `/auth/login?next=…`.** The path-validation regex permitted `//attacker.example/path` because `/` is in the character class and the anchored regex only required a single leading `/`. Patched: dedicated `isSafeNext()` helper rejects `//`, `/\`, oversized values, and now backs both the GET render and the POST redirect.
- **LOW — `lifeline:askit` correct-answer broadcast** reached every WebSocket connection, including unauthenticated listeners with no `player:join`. Patched: broadcast filter now requires `player` / `host` / `admin` role.
- **LOW — SSRF redirect bypass in `fetchTextSafe`.** The initial URL was validated, but `fetch({ redirect: 'follow' })` would chase 30x responses to `http://`, private IPs, or loopback without re-running the guards. Patched: `redirect: 'manual'`, every `Location` re-validated through `assertSafeFetchUrl`, redirect chain capped at 3 hops.
- **LOW — HTTPS redirect echoed `req.headers.host`.** A forged `Host` header on a non-TLS deploy could be redirected to `https://attacker.example/…`. Patched: redirect target is now built from `branding.publicBaseUrl` / `PUBLIC_BASE_URL`; a 400 is returned if neither is set so the operator's misconfiguration is loud, not silently exploitable.
- **Defence-in-depth — Generic error-handler middleware.** Express's default error renderer was echoing JS stacks back to the client when middleware threw (visible during F1 testing on the HTTP path). Replaced with a tail handler that logs the error and returns a plain `Server error` body in every `NODE_ENV`.
- **Defence-in-depth — `COOKIE_SECRET` is now required in production**, matching the existing fatal check for `HOST_TOKEN` and `ADMIN_TOKEN`. Restart-driven session rotation was a UX foot-gun, not a security gap, but worth being explicit about.

### Added

- 32 new regression tests under "F1: … F7: …" headings in `test/security.test.js` (487 → 519 checks). Each finding has at least one unit + one end-to-end assertion.
